Buổi 34: Ôn tập và sửa lỗi logic

Bài giảng chi tiết cho tiết học 90 phút: lý thuyết, ví dụ code, giải thích từng bước, bài tập trên lớp và bài tập về nhà.

Lý thuyếtNội dung được triển khai chi tiết theo từng khái niệm.
Code mẫuCác ví dụ C++ console có giải thích từng bước.
Thực hànhBài tập trên lớp và bài tập về nhà rõ yêu cầu.

1. Mục tiêu buổi học

  • Ôn tập toàn bộ xử lý danh sách, tìm kiếm, sắp xếp.
  • Biết phân biệt lỗi biên dịch và lỗi logic.
  • Biết dùng cout trung gian để debug.
  • Biết tạo bộ test nhỏ để kiểm tra chương trình.
  • Biết sửa lỗi sai điều kiện, sai chỉ số, sai thứ tự sắp xếp.
  • Học sinh sửa được mini app để chạy ổn định hơn.

2. Lý thuyết chi tiết

  • Lỗi biên dịch (Syntax Error): Là những lỗi chữ màu ĐỎ do viết sai ngữ pháp (quên dấu chấm phẩy, khai báo biến sai tên). Trình biên dịch C++ sẽ cấm không cho bạn chạy. Lỗi này rất dễ sửa vì máy tính đã chỉ điểm đích danh số dòng bị lỗi.
  • Lỗi Logic (Bugs): Đây là ác mộng thực sự. Chương trình không hiện lỗi đỏ, chạy bình thường, nhưng kết quả tính toán sai bét (ví dụ: Tính tổng 2+2 lại ra 5). Lỗi này do chính tư duy con người bị sai (sai điều kiện if, sai công thức, sai chỉ số i).
  • Kỹ thuật Debug bằng cout: Để truy bắt lỗi Logic, lập trình viên sẽ chèn các lệnh cout (đóng vai trò như các trạm kiểm soát) vào giữa các hàm. Việc này giúp theo dõi xem biến dữ liệu đang mang giá trị bao nhiêu tại một thời điểm cụ thể.
  • Test Case nhỏ: Đừng bao giờ nhập 100 thông tin để test ứng dụng. Hãy tạo sẵn một bộ 3 dữ liệu Test siêu nhỏ bằng cách code cứng (hardcode) trực tiếp vào vector trong main. Test xong thấy code đúng thì mới xóa bộ test đó đi và đưa cho người dùng nhập thật.
Minh họa chi tiết

Ý tưởng trực quan: Một thám tử cầm kính lúp (đại diện cho lệnh cout trung gian) soi vào một đường ống (Luồng dữ liệu code) để tìm ra một con bọ (Bug/Lỗi logic) đang làm tắc đường ống

  • Cách trình bày: Vẽ đường ống dữ liệu có điểm bị tắc. Kính lúp cout được đặt ở các bước trung gian để xem dữ liệu đang biến đổi ra sao.
  • Ví dụ thao tác: Chèn cout << "i = " << i << endl; hoặc cout << "size = " << v.size() << endl; để tìm lỗi logic.
  • Điểm cần chốt: Chốt rằng lỗi logic không làm chương trình dừng, nhưng kết quả sai; cần in trung gian và test nhỏ để khoanh vùng.
  • Câu hỏi kiểm tra nhanh: Khi kết quả tổng bị sai, nên in biến nào để kiểm tra từng bước?

3. Ví dụ minh họa

Ví dụ 1: Truy bắt lỗi logic bằng cout trung gian

#include <iostream>
using namespace std;

int main() {
    int n = 5;
    int tong = 1; // BUG LOGIC: Đáng ra tổng phải bắt đầu từ 0

    cout << "--- KHOI DONG DEBUG ---\n";
    for (int i = 1; i <= n; i++) {
        tong = tong + i;
        // Chèn cout vào để nhìn xuyên thấu dữ liệu
        cout << "[DEBUG] Vong lap " << i << ": tong hien tai = " << tong << "\n";
    }

    cout << "Ket qua cuoi cung: " << tong << "\n";
    return 0;
}

Giải thích: Khi chạy, lập trình viên sẽ thấy [DEBUG] Vong lap 1: tong hien tai = 2. Từ đó lập tức phát hiện ra lỗi bất thường vì 1 + 1 không thể ra 2 nếu tổng ban đầu là 0, từ đó sửa lại int tong = 0;.

Ví dụ 2: Tạo bộ test nhỏ (Hardcode) đỡ tốn công gõ phím

#include <iostream>
#include <vector>

4. Bài tập thực hành trên lớp

  • Bài 1: Giáo viên cung cấp một đoạn code tính điểm trung bình (cố tình viết sai công thức cộng dồn). Học sinh phải chèn lệnh cout vào trong vòng lặp để tìm ra dòng code gây lỗi.
  • Bài 2: Dùng bộ test cứng (hardcode), kiểm tra chéo các hàm Xóa erase() của mình xem có bị lỗi "Xóa sai chỉ số" không (vd nhập xóa vị trí 1 nhưng máy tính lại bay mất vị trí 0).

5. Bài tập về nhà

  • Bài 1: Chuẩn bị tinh thần và làm sạch toàn bộ Code của Mini App cá nhân. Khắc phục tất cả những lỗi vặt (nhập sai chữ, sai khoảng trắng, rớt phần mềm) để ứng dụng có thể chạy mượt mà, không bao giờ bị Crash.

6. Checklist cuối buổi

  • Lỗi logic nguy hiểm hơn lỗi cú pháp (biên dịch) ở chỗ nào?
  • Làm sao để biết một vòng lặp for có đang chạy đúng số vòng hay không mà không cần đoán? (Dùng cout!).
  • Chúc mừng! Giai đoạn 3 đã hoàn tất. Bạn đã sở hữu một phần mềm quản lý chạy được trên console rồi đấy! Sẵn sàng bảo vệ dự án nhé.
Minh họa chi tiết

Ý tưởng trực quan: ...

  • Cách trình bày: Chuyển mô tả này thành một sơ đồ đơn giản trên bảng: chia thành các khối, mũi tên và nhãn ngắn để học sinh nhìn được luồng xử lý.
  • Ví dụ thao tác: Sau khi vẽ, gắn ngay với một đoạn code hoặc một bộ dữ liệu nhỏ trong bài để học sinh không chỉ nhìn hình mà còn biết áp dụng.
  • Điểm cần chốt: Chốt lại bằng một câu: minh họa này tương ứng với khái niệm nào trong C++ và khi nào cần dùng.
  • Câu hỏi kiểm tra nhanh: Yêu cầu học sinh tự tạo thêm một ví dụ tương tự rồi giải thích lại bằng lời.
